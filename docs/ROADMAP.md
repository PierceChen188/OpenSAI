# OpenSAI Phase 2 路线图（协同感知 + 适配优化 + 资源控制）

> 一句话目标：把这套 DAG 卸载平台，做成一个**协同感知**系统——能根据**真实监测**，
> 智能决定任务**放到哪台设备**(放置)、**给多少资源**(分配)，并在设备间**直传特征**(数据面)。
>
> 推进次序（固定）：**监测 → 资源控制 → 适配优化(决策)**。先有测量，才谈得上控制与决策。
> 控制面(TCP 星型)是稳定地基，**不动**；新增能力都落在数据面 / 决策层 / 监测层。

## 闭环逻辑

```
        ┌──────────── 反馈(真实耗时/带宽/负载) ───────────┐
        ▼                                                │
 ① 监测            ② 决策(server·适配优化)        ③ 控制(device·资源控制)
 设备上报:         对每个就绪子任务:                算力: 容器按配额起/复用 → 跑算法
  · 算力(可用/已承诺)  · 放置: 数据在哪/资源够不够/链路代价 → 选设备   网络: 把产出传给下游
  · 网络(每路带宽/时延) · 分配: 按计算量/通信量 → 给多少 CPU+带宽       (单路基准/多网卡聚合, 限速)
        │            · 立即更新预留账本(防超卖)              │
        ▼            · 调用 device 资源控制接口 ────────────┘
 Redis: 设备资源 + 链路质量 + 账本        ④ 数据面: 上游产特征 → 直传 → 下游作为输入
```

## 关键概念

- **智能放置 (T3.1)** = 决定任务在**哪台**设备跑，综合四类信号权衡：
  1. **位置感知**：下游放到已持有其输入数据的设备 → 跨设备传输归零（最大赢点）。
  2. **资源感知**：避开 CPU/内存/队列繁忙的设备（用真实监测）。
  3. **链路代价**：必须传时，挑到数据所在机链路最好的设备（用链路遥测）。
  4. **预留账本**：放置即扣减资源，防止把任务堆到同一台「看似空闲」的机器（防超卖）。
- **精准放置** = 给智能放置喂**实测**而非**估计**的链路信号（需 ①.2/T1.2 主动探测），
  使链路代价那一项可靠。智能放置=会权衡的脑子；T1.2=准确的眼睛。
- **放置(T3.1, WHERE) ≠ 资源档位(T3.2, HOW MUCH)**：一个选机器、一个给配额，先做 T3.1。
